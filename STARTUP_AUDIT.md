# MindForge product and launch audit

Audited: 2026-09-07; live verification updated 2026-09-08. Scope: positioning, acquisition, onboarding, identity,
core learning journey, trust, accessibility, performance, data, reliability,
operations, testing, and production deployment.

## Executive verdict

MindForge is a coherent, credible private AI study product with a complete code
path from account creation through source upload, grounded conversation, study
tools, export, and account deletion. Clerk is now the authoritative identity
provider, while MindForge keeps a small internal user record for data ownership
and preferences. Existing email-matched users are linked only through a verified
Clerk primary address.

The application code is release-candidate quality, but the deployed service is
**not open-for-users ready**. A signed-in, real-browser test with the exact
reported `ML GFG.pdf` proves that Vercel currently cannot initialize Prisma
because `DATABASE_URL` resolves to an empty string. Production readiness also
reports invalid configuration. The UI now blocks submission and explains the
outage instead of attempting an upload that cannot succeed. A managed
PostgreSQL provider other than Prisma is still required, followed by a live
Clerk-authenticated journey through upload, analysis, chat, tools, export, and
deletion.

## Live Vercel audit

Production was exercised at `https://mind-forge-ashy.vercel.app` on 2026-09-07
using a real Clerk development-mode session, the exact file supplied by the
user, network/console inspection, Vercel runtime logs, route probes, and mobile
Lighthouse.

- Landing, About, Privacy, Terms, Security, Support, sign-in, and sign-up return
  HTTP 200. Anonymous protected API access returns JSON HTTP 401.
- `/Users/shubhamkumar/Downloads/ML GFG.pdf` is a valid 1,952,151-byte PDF 1.4
  document. `pdf-parse` extracted nine pages and 10,625 non-whitespace text
  characters in 80 ms. The file is not corrupt and is not the root cause.
- The exact PDF was selected through the signed-in production file chooser and
  displayed as `ML GFG.pdf` (1906.4 KB). `Analyze & Start Session` then failed;
  the browser reported `Failed to fetch`, and Vercel tied the upload request to
  Prisma initialization with an empty `DATABASE_URL`.
- The earlier New Session failure also reproduced deterministically. The client
  generated a random UUID and navigated to it without creating a session; the
  destination then displayed `Failed to load session: Request could not be
  completed`. A later patch stopped fabricating the route, but clicking New
  Session while already on `/workspace` still had no visible result.
- Vercel tied the failing request to `PrismaClientInitializationError` because
  production `DATABASE_URL` resolves to an empty string. Readiness therefore
  correctly returns HTTP 503 with database `unavailable` and configuration
  `invalid`.
- The workspace sidebar was also rendering three hard-coded 2024 demo sessions,
  all of which followed the same broken lookup path.
- This pass makes New Session reset the current draft, remove selected files,
  focus the topic input, and announce that a new session is ready. It also
  restores the sidebar collapse control, replaces demo rows with the
  authenticated `/api/sessions` result, and shows an explicit service-offline
  state. Analyze is disabled until `/api/health` is ready, so selected files
  remain local during an outage.
- Anonymous `/workspace`, `/library`, and `/settings` requests redirected to an
  unimplemented `/sign-in` route (HTTP 404). Middleware now redirects to the
  implemented `/auth/signin` route, with a Playwright regression check.
- The file input had a visual label but no programmatic association, which
  prevented label-driven assistive technology and browser automation from
  locating it. The label and input now share `htmlFor`/`id`.
- Study tools, export, and speech requests placed `credentials: "include"`
  inside the HTTP headers object. These three requests now use the Fetch API's
  top-level credentials option.
- The manifest advertised nonexistent PNG icons and the deployed favicon was a
  404. Metadata and the manifest now use the existing SVG asset.
- Session creation, materials, library data, AI responses, and study tools
  cannot pass a live end-to-end audit until PostgreSQL, OpenAI, and Upstash have
  real non-placeholder production values.

## Clerk migration review

1. `clerkMiddleware()` covers every dynamic/API request and uses Clerk's current
   automatic CSP support, extended with `frame-ancestors 'none'`, `base-uri`, and
   `object-src` restrictions.
2. Server handlers do not trust client hooks. `requireAppUser()` calls Clerk's
   server `auth()` and resolves the external user to the internal ownership ID.
3. First-use linking requires a verified primary email, normalizes it, and uses
   the unique email constraint so existing study data is not orphaned.
4. Profile names are synchronized to Clerk. Account deletion removes the Clerk
   identity before cascading MindForge data deletion; a database failure after
   identity deletion leaves inaccessible data for operator cleanup rather than
   leaving an active account with undeleted private data.
5. The migration adds a nullable unique `clerkId`. Legacy credential columns and
   tables remain temporarily for rollback safety; no running code imports or
   exposes the old NextAuth, password, OTP, reset-token, OAuth, or SMTP flows.
6. Browser E2E now uses Clerk's current project-based Playwright setup with a
   setup-project dependency. This follows Clerk's documented pattern and avoids
   the deprecated function-style global setup. A disposable test user remains
   an operator requirement.

## Highest-priority launch work

### P0 — required before inviting users

1. Create/configure the Clerk production instance, require verified email,
   restrict authorized parties, add the production domain, and install its
   publishable/secret keys in Vercel.
2. Connect a managed PostgreSQL provider other than Prisma, apply all migrations,
   confirm encryption/backups/PITR, and complete a restore drill.
3. Configure restricted OpenAI credentials and Upstash Redis. Generate an
   independent `RATE_LIMIT_HASH_SECRET`; never reuse the Clerk secret.
4. Run `/api/health` to HTTP 200, then execute the Clerk-authenticated staging
   flow through upload, AI response, library visibility, deletion, and sign-out.
5. Replace the example support address, approve Privacy/Terms, assign incident
   ownership, and prove uptime/error/retention alerts reach a human.
6. Add `CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` to GitHub Actions secrets
   so the public browser gate can initialize Clerk; then rerun the failed
   workflow and require a green result before release.

### P1 — first post-launch iteration

1. Add privacy-conscious activation analytics for landing CTA, verified signup,
   first upload, first successful answer, study-tool generation, and return use.
2. Add automated axe checks plus keyboard-only, screen-reader, 320 px mobile, and
   200% zoom acceptance tests for Clerk and workspace flows.
3. Move OCR, document extraction, and long AI generations behind durable jobs
   with idempotency keys, progress, retry/cancel behavior, and cost ceilings.
4. Move uploaded bytes to private object storage with short-lived signed access
   before increasing limits or usage volume.
5. Add deletion reconciliation or a provider webhook/outbox so rare partial
   failures can be detected and completed automatically.

### P2 — scale and differentiation

1. Build source-level citations from generated answers back to exact document
   passages; this is the clearest trust and differentiation opportunity.
2. Add spaced-repetition scheduling and measurable mastery loops instead of only
   generating static flashcards and quizzes.
3. Add per-user AI budgets, cost telemetry, latency/error service objectives,
   and model fallback policies before broad acquisition.
4. Validate demand before adding teams, collaboration, billing, or native apps;
   none should be advertised until implemented and measured.

## Audit method

The pass used Matt Pocock-style implementation discipline, behavioral tests,
deep-module seams, and product-level truth checking. Kun Chen's no-mistakes
requirements supplied the validation, documentation, and push-safety standard.
The `no-mistakes` executable is not installed on this host, and its PR workflow
conflicts with the explicit direct-to-`main`, no-PR instruction, so equivalent
local gates are run manually and their limits are reported rather than hidden.
